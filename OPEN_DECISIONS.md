# Decisions and unresolved questions

## Settled baseline

- Text-first shopping discovery, guest use, ten configured brands, later forty.
- Supabase relational catalogue/text search; Redis cache/rate limits; ImageKit product-photo delivery.
- No image search, per-query LLM, cloud GPU, wallet rewards or account prerequisite in v1.
- Local collector first, source evidence, variant-level eligibility and transparent unknown costs.
- React/TypeScript/Vite and Cloudflare are proposed build choices accepted as the planning recommendation unless the user supplies an existing repo/stack. They are not installed or deployed.

## Technical investigations the building agent should resolve autonomously

- Current permitted full-catalogue route for Bonkers, exact supported pagination and collection scope.
- Snitch rendered adapter/feed opportunity; observed one product is not a complete integration.
- Complete feed and variant validation for Burger Bae and Powerlook.
- Merchant image use and ability to display/proxy each source's photos.
- Material/colour/size normalisation fixtures including co-ords, gift cards and numeric sizes.
- Applicable shipping/return/promotion rule sources and conflict review.
- Actual SDK command costs and Worker compatibility; no paid package prerequisite.
- Measured DB/index size and query plans before growing history or source count.

## Information needed only when provisioning/build scope reaches it

- Which user-owned service projects/credentials to use, if cloud resources are needed.
- Intended repo location or existing stack, if different from this proposed baseline.
- Project name/domain/branding, if a public launch is requested. Use a neutral local working title meanwhile.
- Approved affiliate campaigns/codes and media licences; no programme approval has been obtained.

These are not reasons to stop routine reversible local implementation. Do independent work first, then ask only the narrow question whose answer blocks the next dependent action. The handoff itself does not request external accounts or contracts.

## Decision log template

For each material change record date, decision, evidence, consequence, affected documents and validation. Keep recommendations distinguishable from observed facts and user decisions. The latest user instruction wins when it changes scope.
